## 1. Constat contradictoire, ligne de partage des responsabilités

Le viewport actuel est **read-only**, construit sur `tk.Canvas`, avec image à `(0,0)`, `anchor='nw'`, `scrollregion=(0,0,display.width(),display.height())`. `fit_factor` utilise `ceil` sur les deux axes ; `_set_scale` utilise `PhotoImage.subsample(factor)` pour facteur entier >1. `fit_scale=None` signifie image originale à 100 %, tandis que `fit_scale=1` peut aussi désigner l'original. `auto_fit` est indépendant. `_show` détruit tous les items et recrée l'image ; aucun item ID stable n'est conservé. `load` réinitialise image, zoom et pan ; `_resize` ne recalcule le fit que si auto-fit. `_start_drag` marque le scan et le drag `<B1-Motion>` fait du **pan**, pas une sélection. Un clic/drag gauche OCR naïf casserait donc le déplacement existant. Le test Tk réel couvre le pan, les touches, le zoom et le remplacement, mais pas la ROI, le DPI Windows ou un oracle pixel.

**Alternative rejetée :** superposer un deuxième Canvas/éditeur ou supposer qu'un clic est une sélection. **Alternative retenue pour étude :** mode explicite `PAN` (comportement V3.4 inchangé) / `ROI_SELECT` (événements distincts) dans le même canvas, sans persistance de masque. Le changement du binding est un travail futur du producteur autorisé, pas de cette tâche.

## 2. Contrat candidat de transformation écran → PNG source

**Source de vérité :** dimensions `W,H` du PNG source validé et SHA exact ; `PhotoImage` est une représentation d'affichage, non la source OCR. Unités : coordonnées pointeur Tk en pixels logiques de widget ; `canvas.canvasx(event.x)` / `canvasy(event.y)` en unités Canvas ; `item_bbox=(ix,iy,ix+dw,iy+dh)` en pixels d'affichage ; facteur de sous-échantillonnage entier `s=fit_scale or 1`. **Ne pas utiliser DPI système comme facteur supplémentaire** : le mapping doit se calibrer sur les dimensions Canvas/PhotoImage observées ; les essais 100/200 % vérifient cette hypothèse.

Pour une sélection rectangulaire par deux extrémités `a,b` en Canvas : normaliser les extrémités, intersecter avec `[ix,ix+dw)×[iy,iy+dh)`, puis convertir les **frontières** source avec `floor(s * (left-ix))`, `ceil(s * (right-ix))` (idem Y), bornées à `[0,W]` et `[0,H]`. Les bornes sont **demi-ouvertes** `[x0,x1)×[y0,y1)` ; rejeter `x0>=x1` ou `y0>=y1`. **Point à qualifier impérativement :** `PhotoImage.subsample` arrondit les dimensions d'affichage des images non divisibles ; une ROI sur la dernière colonne/ligne ne garantit pas à elle seule la couverture des pixels résiduels source. Le contrat doit choisir explicitement soit (A) l'inclusion conservatrice du reliquat si la sélection atteint le bord affiché, soit (B) le refus de prétendre une sélection pixel exacte à ce bord. Ne pas figer la formule comme PASS avant fixture 1001×503 / facteur 3 et contrôle réel des dimensions Tk. Les pixels non visibles par subsample ne sont jamais une preuve de reconnaissance OCR.

**Snapshot immuable au début du geste** : `{source_sha, source_width_px, source_height_px, project_revision, viewport_generation, image_generation, display_width_px, display_height_px, scale_integer, image_origin_canvas, canvas_scroll_offsets, roi_mode}`. C'est un **contrat proposé**, aucune classe/API existante affirmée. Un pan/zoom, resize auto-fit, `load`, nouvelle source ou changement de révision pendant le geste invalide le snapshot : afficher « sélection à refaire », sans commit. Le worker OCR, s'il est ultérieurement autorisé, reçoit un crop des pixels source et renvoie une **proposition éphémère** ; résultat stale/annulé refusé avant validation humaine. Ne pas ajouter de TextNode V1 ni de migration implicite V2.
