# R15 durable PR checkpoint — phase 1
A/B may append one line to an actual substantive PR review comment:
`R15_CHECKPOINT_V1 {"version":1,"number":195,"head":"<40 hex>","main":"<40 hex>","policy_blob":"<40 hex>","role":"B","verdict":"PARTIAL"}`.
Only exact current HEAD/main/policy; role opposite branch writer; verdict PARTIAL, ADVERSE, FAVORABLE. Do not edit a checkpoint; append a new real finding when evidence changes. No scheduler ID, raw log, credentials or private data. A marker is optional and must never replace semantic review. The shared GitHub identity cannot prove which agent produced it. The read-only controller rereads the comment, PR branch and main; valid hints influence only the next inspection. Existing CI failure, owner scope and correlated review precedence remain. This is durable comment-based continuity, not a persistent lease, scheduler bridge, or merge authorization. A missing hint falls back to normal R13 routing. No new credential or paid service. Generalization still requires the real pilot, authenticated private scheduler correlation, incident recovery and bounded journal rotation.
